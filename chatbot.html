Case study / Conversational AI

AI Portfolio Assistant

A production RAG chatbot that knows my work. Visitors ask it anything and it answers in real time, pulling context from a vector database of my portfolio content. Orchestrated entirely with self-hosted n8n, reasoning with Claude Haiku 4.5, grounded by Pinecone semantic search.

01 / Problem & solution

A static page cannot answer a question.

The problem

Visitors leave without answers

People have specific questions about a developer's experience that bullet points and project tiles never cover. Without an answer they leave, and without context they leave without making contact.

The solution

An assistant that reads the source

An n8n-orchestrated assistant using retrieval-augmented generation. It searches a vector store of my portfolio knowledge, feeds that context to Claude, and replies in my voice — around the clock, with conversation memory and session tracking.

03 / Step by step

What actually happens
between question and answer.

  1. 01

    The visitor sends a message

    The widget on the portfolio POSTs {message, sessionId} to the n8n webhook. The session ID persists in localStorage so a reload does not lose the thread.

  2. 02

    Extract Input normalises the body

    It generates a session ID when one is missing and forwards a clean {chatInput, sessionId} downstream.

  3. 03

    The agent assembles its prompt

    Hardcoded facts about me, the last fifteen messages from window buffer memory, and access to the portfolio_knowledge tool.

  4. 04

    Retrieval fires only when needed

    If the question needs depth, the agent calls the tool, which embeds the query with HuggingFace all-mpnet-base-v2, queries the Pinecone hassan-website namespace, and feeds the top matches back.

    Fast answers stay fast
  5. 05

    Claude Haiku 4.5 writes the answer

    It synthesises the reply in my voice. From here the output fans out twice, in parallel.

  6. 06

    Respond to Webhook ships the reply

    It returns {reply, success: true} with proper CORS headers, and the visitor sees the answer.

  7. 07

    Save to Firebase logs the turn

    The conversation is written to chatbot/conversations in Realtime Database for analytics. This branch never blocks the response, and a failure here cannot break the reply.

n8n

Self-hosted workflow orchestrator. Defines the trigger, runs the agent, routes responses.

Runs on my own server
Reasoning

05 / Capabilities

The details that make it
hold up in production.

  • Retrieval-augmented generation Vector search runs only when the question needs it, so simple answers stay fast.
  • Conversation memory The last fifteen turns stay in context per session. Nobody has to repeat themselves.
  • Session persistence A browser-side session ID survives reloads through localStorage.
  • Parallel side effects Firebase logging runs beside the reply and never delays it.
  • Lead intent detection The system prompt routes hiring questions toward name and email capture.
  • Production CORS Origin-restricted headers, so only the portfolio domain can call the webhook.
  • Graceful degradation Network errors render an inline retry message rather than a broken bubble.
  • Zero framework The widget is plain JavaScript and drops into any static site.
